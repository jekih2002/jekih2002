1.1디지털 트윈의 정의와 기원★★★물데모서▶
핵심 정리
  • 디지털 트윈은 물리 자산·공정·시스템의 상태를 실시간 데이터로 동기화한 가상 모델이며, 분석·예측·최적화 결과를 다시 물리 세계에 환류하는 양방향 체계를 의미한다.
  • 개념적 기원은 2002년 미시간 대학교 Michael Grieves가 PLM 강연에서 제시한 '제품 수명주기 관리를 위한 개념적 이상형(Conceptual Ideal for PLM)'이며, 물리 공간·가상 공간·양자를 잇는 데이터 연결의 3요소로 구성된다.
  • 용어 'Digital Twin'은 2010년 NASA 기술 로드맵(John Vickers)에서 비행체의 고충실도 다중물리 시뮬레이션으로 정식화되었으며, 원형은 1970년 아폴로 13호의 지상 시뮬레이터 운용에 있다.
  • ISO 23247(제조 디지털 트윈 프레임워크)은 디지털 트윈을 '관측 가능한 제조 요소에 대한 목적 지향적 디지털 표현으로서 요소와 표현 사이에 동기화가 이루어지는 것'으로 정의한다.
  • 디지털 트윈의 본질은 3D 형상이 아니라 '동기화(synchronization)'와 '목적(purpose)'에 있으며, 형상이 없는 공정·조직·도시 트윈도 성립한다.
공식 · 구조
디지털 트윈 기본 구성 (Grieves)
DT = ⟨ 물리 실체 PE , 가상 실체 VE , 연결 C(PE→VE 데이터, VE→PE 정보) ⟩
3요소 중 연결의 양방향성이 트윈을 단순 모델과 구분하는 기준이다.
5차원 모델 (Tao, 2018)
DT = ⟨ PE , VE , Ss , DD , CN ⟩
물리 실체·가상 실체·서비스·트윈 데이터·연결의 5요소로 확장한 모델이다.
강의 연계 · 실습 · 사례
강의오리엔테이션
디지털 트윈과 단순 3D 시각화의 차이를 설명하라
3D 시각화는 형상 재현에 그치나, 디지털 트윈은 실시간 동기화·상태 추정·예측·환류 제어를 포함하는 폐루프 체계이다.
오해 · 함정
주의디지털 트윈을 '3D 모델'과 동일시하는 서술은 감점 요인이다. 핵심은 데이터 연결과 동기화이다.
1.2디지털 모델 · 디지털 섀도 · 디지털 트윈★★★물데모서▶
핵심 정리
  • Kritzinger 등(2018)은 데이터 흐름의 자동화 정도에 따라 세 유형을 구분한다.
  • 디지털 모델(Digital Model)은 물리↔가상 간 데이터 교환이 모두 수동인 모델이며, 설계 단계 CAD·시뮬레이션 모델이 해당한다.
  • 디지털 섀도(Digital Shadow)는 물리→가상 방향만 자동 동기화되고, 가상→물리 방향은 수동인 모델이며, 모니터링 대시보드가 대표적이다.
  • 디지털 트윈(Digital Twin)은 양방향 모두 자동으로 데이터가 흐르며, 가상 측의 판단이 물리 측의 제어 명령으로 자동 반영된다.
  • 확장 개념으로 디지털 스레드(수명주기 전 단계 데이터의 연결선), 디지털 트윈 프로토타입(DTP)·인스턴스(DTI)·집합체(DTA)가 존재한다.
공식 · 구조
자동화 수준 판별표
모델: P→V 수동, V→P 수동 / 섀도: P→V 자동, V→P 수동 / 트윈: P→V 자동, V→P 자동
방향별 자동화 여부만으로 유형이 결정된다.
강의 연계 · 실습 · 사례
사례실무 분류
설비 진동을 실시간 표시하고 작업자가 판단하여 속도를 조정하는 시스템의 유형은?
물리→가상 자동, 가상→물리 수동이므로 디지털 섀도이다.
오해 · 함정
주의실시간 대시보드만으로 '디지털 트윈 구축 완료'라고 표현하는 것은 엄밀히는 디지털 섀도에 해당한다.

  • 수명주기 관점에서 DTP(설계 원형), DTI(개별 제품 인스턴스), DTA(인스턴스 집합의 통계적 집합체), DTE(운용 환경)로 구분한다.
  • 성숙도 모델은 대체로 레벨 1 기술(Descriptive) → 2 진단(Diagnostic) → 3 예측(Predictive) → 4 처방(Prescriptive) → 5 자율(Autonomous)의 5단계로 기술된다.
  • Digital Twin Consortium의 Capabilities Periodic Table은 데이터 서비스·통합·지능·UX·관리·신뢰성의 6개 군 60여 역량으로 트윈을 진단하는 도구이다.
  • 국내 '디지털 트윈 국토' 및 스마트시티 사업은 레벨 1 현실 모사 → 2 관제 → 3 분석 → 4 최적화 → 5 자율 운영의 단계 모형을 사용한다.

2.1디지털 트윈 계층 아키텍처★★★물데모서▶
핵심 정리
  • 일반적 계층은 물리 계층(자산·센서) → 연결 계층(통신·게이트웨이) → 데이터 계층(수집·저장·정제) → 모델 계층(형상·물리·데이터 모델) → 서비스 계층(시각화·분석·제어) → 사용자 계층으로 구성된다.
  • 각 계층은 느슨한 결합(loose coupling)과 표준 인터페이스로 분리하여 장비·플랫폼 교체 시 영향 범위를 제한한다.
  • 동기화 경로(상향: 상태 데이터)와 제어 경로(하향: 명령·설정값)를 분리 설계하고, 하향 경로에는 권한 검증·안전 인터록을 둔다.
  • 실시간성 요구에 따라 엣지(ms 단위 제어)–포그(초 단위 분석)–클라우드(분·시 단위 학습)로 연산을 배치한다.

2.2ISO 23247 제조 디지털 트윈 프레임워크★★★물데모서▶
핵심 정리
  • ISO 23247은 2021년 제정된 제조 분야 디지털 트윈 프레임워크 표준이며, Part 1(개요·원칙), Part 2(참조 아키텍처), Part 3(관측 가능 제조 요소의 디지털 표현), Part 4(정보 교환)로 구성된다.
  • 참조 모델은 관측 가능 제조 요소(OME) / 장치 통신 엔터티 / 디지털 트윈 엔터티 / 사용자 엔터티의 4개 도메인으로 구성된다.
  • 디지털 트윈 엔터티는 운영·관리, 응용·서비스, 자원 접근·교환의 하위 엔터티로 나뉜다.
  • OME에는 인력, 장비, 자재, 공정, 시설, 환경, 제품, 지원 문서가 포함된다.

2.3RAMI 4.0과 자산관리셸(AAS)★★★물데모서▶
핵심 정리
  • RAMI 4.0은 독일 Industrie 4.0의 3차원 참조 모델로, 계층(Asset~Business 6층), 수명주기·가치흐름(IEC 62890 Type/Instance), 위계(IEC 62264/61512: Product~Connected World)의 3축으로 구성된다.
  • I4.0 컴포넌트 = 자산 + 자산관리셸(AAS)이며, AAS는 자산의 디지털 표현을 표준화한 디지털 트윈의 구현 규격이다.
  • AAS는 서브모델(Submodel) 단위로 기술 데이터·명판·운전 데이터·문서 등을 구성하며, IDTA(Industrial Digital Twin Association)가 서브모델 템플릿을 관리한다.
  • AAS는 IEC 63278 시리즈로 국제표준화되었으며 Type 1(파일, AASX), Type 2(REST API 서버), Type 3(능동형, 자율 협상)의 세 유형이 있다.
  • 서브모델 요소는 IEC 61360/ECLASS 의미 식별자(Semantic ID)로 의미를 정의하여 기계 해석 가능성을 확보한다.
공식 · 구조
AAS 구조
AAS = { 식별자(globalAssetId), AssetInformation, Submodel₁…ₙ { SubmodelElement(Property·Collection·Operation…) + semanticId } }

2.4트윈 데이터 모델링 언어 — DTDL·NGSI-LD·온톨로지★★물데모서▶
핵심 정리
  • DTDL(Digital Twins Definition Language)은 Azure Digital Twins의 JSON-LD 기반 모델 언어로 Interface, Property, Telemetry, Command, Relationship, Component를 정의한다.
  • NGSI-LD는 ETSI가 표준화한 맥락 정보 관리 API로 FIWARE 스마트시티 플랫폼의 기반이며, Entity–Property–Relationship 그래프 모델을 사용한다.
  • 온톨로지(OWL/RDF)·지식 그래프는 설비·공정·제품 간 의미 관계를 기계 추론 가능하게 표현하며, Brick Schema(건물), SAREF(스마트 가전), RealEstateCore 등이 대표적이다.
  • 데이터 모델 설계 시 정적 속성(Property)과 동적 시계열(Telemetry), 관계(Relationship)를 분리하는 것이 확장성의 핵심이다.

2.5상호운용성과 국제 표준 지형★★물데모서▶
핵심 정리

  • ISO/IEC JTC 1/SC 41은 IoT·디지털 트윈 일반 표준(ISO/IEC 30173 개념·용어, 30172 사용 사례, 30188 참조 아키텍처)을 담당한다.
  • IEC 62264(ISA-95)는 기업–제어 시스템 통합의 계층(L0~L4)과 정보 모델을 정의하여 MES–ERP–트윈 간 데이터 교환의 기준이 된다.
  • 건설은 IFC(ISO 16739), 지리공간은 OGC CityGML·3D Tiles, 시뮬레이션은 FMI, 3D 장면은 OpenUSD·glTF가 주요 교환 표준이다.
  • Digital Twin Consortium, IDTA, Alliance for OpenUSD, OPC Foundation 등 컨소시엄 표준이 공적 표준보다 먼저 시장을 주도하는 경향이 있다.
공식 · 구조

3.1센서의 원리와 선정★★★물데모서▶
핵심 정리
  • 산업용 주요 센서는 온도(열전대·RTD·서미스터), 압력(피에조저항·정전용량), 진동(가속도계: IEPE 압전·MEMS), 유량(전자기·코리올리·초음파), 전류(CT·홀), 위치(엔코더·LVDT)이다.
  • 선정 기준은 측정 범위, 정확도·정밀도, 분해능, 응답 시간, 대역폭, 환경 내성(IP 등급, 방폭), 출력 형식(4–20 mA, 0–10 V, 디지털)이다.
  • 4–20 mA 전류 루프는 4 mA를 영점(live zero)으로 하여 단선(0 mA) 검출이 가능하고 장거리 잡음에 강하다.
  • 스마트 센서는 IO-Link 등 디지털 인터페이스로 측정값과 진단·파라미터 정보를 함께 전달하여 트윈의 자산 정보 모델을 풍부하게 한다.
공식 · 구조
4–20 mA 환산
측정값 = Lo + (I − 4) / 16 × (Hi − Lo)
I < 3.8 mA 또는 > 20.5 mA는 NAMUR NE43에 따라 고장 신호로 판정한다.
정확도와 정밀도
정확도 = |평균 − 참값| (편향) / 정밀도 = 반복 측정의 표준편차 (산포)
교정(calibration)은 편향을, 평균화는 산포를 줄인다.
강의 연계 · 실습 · 사례
계산실습
0~10 bar 압력 전송기의 출력이 12 mA일 때 압력은?
0 + (12 − 4)/16 × 10 = 5 bar이다.
오해 · 함정
주의분해능이 높다고 정확도가 높은 것은 아니다. 분해능은 최소 구분 단위, 정확도는 참값과의 근접도이다.
3.2샘플링·ADC·신호 전처리★★★물데모서▶
핵심 정리
  • 나이퀴스트–섀넌 정리에 따라 샘플링 주파수는 신호 최고 주파수의 2배를 초과해야 하며, 실무에서는 2.56배(진동 분석) 이상을 적용한다.
  • 앨리어싱 방지를 위해 ADC 앞단에 아날로그 저역통과 필터(anti-aliasing filter)를 둔다.
  • ADC 분해능 n비트의 양자화 단계는 FS/2ⁿ이며, 이상적 SNR은 약 6.02n + 1.76 dB이다.
  • 디지털 전처리는 이동평균·지수평활·중앙값 필터(스파이크 제거)·버터워스 필터 등을 사용하며, 위상 지연이 트윈 동기화 오차로 이어지는 점에 유의한다.
  • 데이터 축약을 위해 데드밴드(변화량 임계 이하 미전송), 스윙도어 압축, 엣지 특징 추출(RMS·첨도·피크)을 사용한다.
공식 · 구조
나이퀴스트 조건
fₛ > 2·f_max
위반 시 f_alias = |f − k·fₛ| 성분이 나타난다.
양자화
Δ = FS / 2ⁿ , SNR ≈ 6.02·n + 1.76 dB
12비트, 10 V FS이면 Δ ≈ 2.44 mV이다.
지수평활
ŷₜ = α·xₜ + (1 − α)·ŷₜ₋₁
α가 작을수록 평활 효과는 크나 지연이 커진다.
강의 연계 · 실습 · 사례
계산실습
최대 1 kHz 진동 성분을 분석하려면 샘플링 주파수는?
이론상 2 kHz 초과, 실무 2.56배 기준 2.56 kHz 이상이다.
오해 · 함정
주의데이터 전송량 절감을 위해 샘플링을 낮추는 것보다, 고속 샘플링 후 엣지에서 특징값을 추출하여 전송하는 것이 정보 손실이 적다.
3.3PLC·SCADA·DCS와 제어 시스템★★★물데모서▶
핵심 정리
  • PLC는 스캔 사이클(입력 읽기 → 프로그램 실행 → 출력 갱신) 방식으로 동작하며 IEC 61131-3의 5개 언어(LD, FBD, ST, IL, SFC)를 사용한다.
  • SCADA는 광역 분산 설비의 감시·데이터 수집을, DCS는 연속 공정(화학·발전)의 통합 제어를 담당한다.
  • 트윈은 PLC 태그·SCADA 히스토리안의 데이터를 수집하는 동시에, 가상 PLC(소프트 PLC) 또는 PLCSIM과 연결되어 가상 시운전을 수행한다.
  • IEC 61499는 분산 제어를 위한 이벤트 기반 기능블록 표준으로, 소프트웨어 정의 자동화(SDA)·가상화 PLC 흐름의 기반이다.
  • 소프트웨어 정의 PLC·컨테이너형 제어(vPLC)는 하드웨어와 제어 로직을 분리하여 트윈과 동일 코드를 공유할 수 있게 한다.
공식 · 구조
PLC 스캔 사이클
T_scan = T_input + T_program + T_output + T_comm
응답 시간 최대치는 약 2 × T_scan으로 산정한다.
강의 연계 · 실습 · 사례
강의가상 시운전
PLCSIM Advanced와 3D 트윈 연결 절차를 제시하라
가상 PLC 실행 → 태그 매핑(OPC UA 또는 S7 통신) → 3D 모델의 센서·액추에이터 신호 연결 → 시나리오 기반 시험이다.
오해 · 함정
주의SCADA를 단순 시각화 소프트웨어로 보는 것은 오류이다. 경보 관리·이력 저장·원격 제어 기능을 포함한다.
3.4엣지 컴퓨팅과 산업용 게이트웨이★★물데모서▶
핵심 정리
  • 엣지 게이트웨이는 이기종 프로토콜(Modbus, S7, EtherNet/IP) 변환, 버퍼링(store-and-forward), 전처리, 보안 경계 역할을 수행한다.
  • 엣지 AI는 추론을 현장에서 수행하여 지연·대역폭·데이터 주권 문제를 해결하며, 모델 경량화(양자화·가지치기·지식 증류)가 필요하다.
  • 컨테이너 기반 엣지 플랫폼(K3s, KubeEdge, Azure IoT Edge, AWS Greengrass)은 클라우드와 동일한 배포 체계를 엣지에 제공한다.
  • 통신 단절 시 로컬 버퍼에 저장 후 재접속 시 순차 전송하여 시계열 결측을 방지하며, 타임스탬프는 수집 시점 기준으로 부여한다.
공식 · 구조
데이터량 산정
일일 데이터량 = 태그 수 × 샘플링(Hz) × 바이트/샘플 × 86 400
대역폭(bps) = 태그 수 × 샘플링 × 바이트 × 8 × (1 + 프로토콜 오버헤드)
강의 연계 · 실습 · 사례
계산실습
태그 500개, 10 Hz, 샘플당 16 B이면 일일 데이터량은?
500 × 10 × 16 × 86 400 ≈ 6.9 GB/일이다.
오해 · 함정
주의엣지에서 타임스탬프를 부여하지 않고 클라우드 수신 시각을 사용하면 버퍼 재전송 시 시간축이 왜곡된다.
3.5시간 동기화와 타임스탬프★★물데모서▶
핵심 정리
  • 다중 센서 데이터를 하나의 트윈 상태로 융합하려면 공통 시간 기준이 필수이다.
  • NTP는 ms 수준, IEEE 1588 PTP는 하드웨어 타임스탬프로 sub-μs 수준 동기화를 제공하며, TSN의 gPTP(IEEE 802.1AS)는 PTP 프로파일이다.
  • 타임스탬프는 원천 시각(source timestamp)과 서버 수신 시각(server timestamp)을 구분 저장하며, OPC UA도 두 시각을 모두 제공한다.
  • 비동기 다중 레이트 데이터는 리샘플링(보간·전방 채움)으로 정렬하되, 보간 방식이 이벤트성 신호를 왜곡하지 않도록 한다.
공식 · 구조
시각 오프셋 (PTP)
offset = [(t₂ − t₁) − (t₄ − t₃)] / 2 , delay = [(t₂ − t₁) + (t₄ − t₃)] / 2
왕복 지연이 대칭이라는 가정에 기반한다.
강의 연계 · 실습 · 사례
계산실습
t₁=0, t₂=110, t₃=200, t₄=290 μs일 때 오프셋은?
[(110) − (90)]/2 = 10 μs, 지연은 100 μs이다.
오해 · 함정
주의이산 상태 신호(ON/OFF)를 선형 보간하면 존재하지 않는 중간값이 생성된다. 계단(zero-order hold) 보간을 사용한다.

4.1OPC UA 정보 모델과 통신★★★물데모서▶
핵심 정리
  • OPC UA(IEC 62541)는 플랫폼 독립적 서비스 지향 아키텍처로, 데이터뿐 아니라 의미를 담은 정보 모델(Address Space)을 제공한다.
  • 주소 공간은 노드(Object, Variable, Method, ObjectType, VariableType, ReferenceType, DataType, View)와 참조(Reference)로 구성된 그래프이다.
  • 통신 방식은 Client/Server(요청-응답, 구독 Subscription·MonitoredItem)와 PubSub(UDP·MQTT 기반, 1:N)이 있다.
  • 보안은 X.509 인증서 기반 상호 인증, 서명·암호화(Sign & Encrypt), 사용자 인증(토큰)으로 구성된다.
  • 컴패니언 스펙(Companion Specification)은 산업별 표준 정보 모델(로봇, 공작기계 umati, PackML 등)로, AAS와 매핑된다.
공식 · 구조
구독 모델
Subscription{PublishingInterval} ⊃ MonitoredItem{SamplingInterval, QueueSize, DeadbandType}
샘플링 간격과 퍼블리싱 간격의 차이를 구분한다.
강의 연계 · 실습 · 사례
실습OPC UA
Python asyncua로 노드 값을 구독하는 절차를 제시하라
서버 접속 → 노드 탐색(NodeId) → Subscription 생성(간격 설정) → 핸들러 등록 → datachange_notification 콜백에서 트윈 상태 갱신이다.
오해 · 함정
주의OPC UA를 단순 '프로토콜'로만 서술하면 불완전하다. 정보 모델링 프레임워크라는 점이 핵심 차별점이다.
4.2MQTT와 Sparkplug B★★★물데모서▶
핵심 정리
  • MQTT는 브로커 중심 발행/구독 경량 프로토콜(TCP 기반)로, 토픽 계층과 와일드카드(+ 단일 레벨, # 다중 레벨)를 사용한다.
  • QoS 0(최대 1회), QoS 1(최소 1회, 중복 가능), QoS 2(정확히 1회, 4-way 핸드셰이크)의 세 수준이 있다.
  • Retained 메시지는 신규 구독자에게 최신값을 즉시 전달하고, LWT(Last Will and Testament)는 비정상 단절을 알린다.
  • MQTT 5.0은 사용자 속성, 메시지 만료, 공유 구독, 응답 토픽 등을 추가하였다.
  • Sparkplug B는 Eclipse 재단 명세로 토픽 네임스페이스(spBv1.0/그룹/메시지유형/노드/장치), Protobuf 페이로드, 출생·사망 인증서(BIRTH/DEATH)로 상태 인지형 MQTT를 정의한다.
공식 · 구조
토픽 구조 (Sparkplug B)
spBv1.0/{group_id}/{NBIRTH|NDATA|NDEATH|DBIRTH|DDATA|DDEATH|NCMD|DCMD}/{edge_node_id}/{device_id}
BIRTH 메시지가 메트릭 정의와 초기값을 선언한다.
강의 연계 · 실습 · 사례
실습MQTT
센서 → Mosquitto 브로커 → 트윈 서비스 파이프라인을 구성하라
paho-mqtt로 factory/line1/press01/temp 토픽 발행(QoS 1) → 트윈 서비스가 factory/+/+/temp 구독 → 시계열 DB 저장 및 3D 객체 상태 갱신이다.
오해 · 함정
주의QoS 2가 항상 최선은 아니다. 고빈도 텔레메트리는 QoS 0/1이 적합하며, QoS 2는 지연·부하가 크다.
4.3필드버스·산업 이더넷·TSN★★물데모서▶
핵심 정리
  • 전통 필드버스는 Modbus RTU, PROFIBUS, CAN이며, 산업 이더넷은 Modbus TCP, PROFINET, EtherNet/IP, EtherCAT이다.
  • EtherCAT은 프레임이 각 슬레이브를 통과하며 즉석 처리(on-the-fly)되어 μs 수준 주기와 분산 클록을 제공한다.
  • Modbus는 코일(0x)·이산입력(1x)·입력레지스터(3x)·보유레지스터(4x)의 네 데이터 영역을 사용하며, 의미 정보가 없어 별도 태그 매핑이 필요하다.
  • TSN(Time-Sensitive Networking, IEEE 802.1)은 시간 동기(802.1AS), 시간 인지 스케줄링(802.1Qbv), 프레임 선점(802.1Qbu) 등으로 표준 이더넷에서 결정적 통신을 구현한다.
  • OPC UA over TSN(OPC UA FX)은 필드 레벨까지 통합된 단일 네트워크를 지향한다.
공식 · 구조
사이클 타임 대략식 (EtherCAT)
T ≈ 프레임 길이 / 100 Mbps + 노드 수 × 노드 지연(≈1 μs)
수백 개 I/O를 100 μs 이하 주기로 갱신 가능하다.
강의 연계 · 실습 · 사례
표준IEEE 802.1
TSN이 트윈의 동기화 품질에 기여하는 방식은?
결정적 지연과 정밀 시간 동기로 다중 장비 데이터의 시간 정합성을 보장하여 상태 추정 오차를 줄인다.
오해 · 함정
주의Modbus 레지스터 주소 표기(40001 vs 0 기반 오프셋)의 1 차이로 잘못된 값을 읽는 오류가 빈번하다.
4.45G·무선 통신과 프라이빗 네트워크★★물데모서▶
핵심 정리
  • 5G는 eMBB(초고속), URLLC(초저지연·고신뢰, 1 ms·99.999%), mMTC(대규모 연결, 10⁶ 기기/km²)의 세 서비스 시나리오를 제공한다.
  • 이음5G(국내 특화망)·프라이빗 5G는 공장 내 이동 로봇·AGV·XR 트윈의 무선 연결 기반이다.
  • 저전력 광역망(LPWAN)인 LoRaWAN·NB-IoT·LTE-M은 저속·장거리 원격 센서(시설물, 상하수도)에 적합하다.
  • Wi-Fi 6/7, Bluetooth LE, UWB(정밀 측위 수십 cm)는 실내 위치 기반 트윈(RTLS)에 활용된다.
  • 6G 비전은 네트워크 자체의 디지털 트윈(Network Digital Twin)과 통신–센싱 통합(ISAC)을 포함한다.
공식 · 구조
무선 링크 예산
P_rx(dBm) = P_tx + G_tx + G_rx − L_path − L_misc , L_fs = 20log₁₀(d) + 20log₁₀(f) − 147.55
d는 m, f는 Hz 단위이다.
강의 연계 · 실습 · 사례
사례스마트 팩토리
5G URLLC가 필요한 트윈 서비스 예시는?
무선 연결 협동로봇의 원격 실시간 제어, AGV 군집의 트윈 기반 경로 재계획, XR 원격 정비이다.
오해 · 함정
주의LoRaWAN은 대역폭이 낮아 고빈도 진동 원신호 전송에는 부적합하다. 엣지 특징값 전송으로 설계한다.
4.5통합 네임스페이스(UNS)와 데이터 연결 아키텍처★★물데모서▶
핵심 정리
  • 점대점(point-to-point) 통합은 시스템 수 n에 대해 최대 n(n−1)/2개의 연결이 필요하여 확장성이 낮다.
  • UNS(Unified Namespace)는 MQTT 브로커를 중심으로 ISA-95 계층(기업/사이트/영역/라인/셀)을 토픽 구조로 하는 단일 실시간 데이터 허브이다.
  • UNS는 '현재 상태의 단일 진실 원천(Single Source of Truth)'을 제공하며, 트윈·MES·ERP·AI가 동일 허브를 구독한다.
  • 이벤트 기반 아키텍처(EDA)와 결합하여 상태 변화 시에만 메시지를 발행(Report by Exception)한다.
공식 · 구조
연결 수 비교
점대점 = n(n−1)/2 , 허브형 = n
n = 10이면 45개 대 10개이다.
강의 연계 · 실습 · 사례
설계UNS
ISA-95 기반 토픽 설계 예시를 쓰라
acme/seoul_plant/assembly/line2/robot03/torque — 기업/사이트/영역/라인/셀/태그의 계층이다.
오해 · 함정
주의UNS가 이력 저장소를 대체하지는 않는다. 현재 상태 허브이며 이력은 시계열 DB·레이크하우스에 별도로 저장한다.

5.1시계열 데이터베이스★★★물데모서▶
핵심 정리
  • 트윈 데이터의 대부분은 (타임스탬프, 태그, 값, 품질)의 시계열이며, 쓰기 집약·시간 범위 조회·다운샘플링이 주요 패턴이다.
  • 대표 제품은 InfluxDB(태그·필드 모델, Flux/SQL), TimescaleDB(PostgreSQL 확장, 하이퍼테이블), QuestDB, TDengine, 산업용 히스토리안(AVEVA PI)이다.
  • 보존 정책(Retention)과 연속 집계(continuous aggregate)로 원시 데이터는 단기, 집계 데이터는 장기 보관하는 계층화 저장을 구성한다.
  • 카디널리티(태그 조합 수) 폭증은 인덱스 비대화로 성능 저하를 일으키므로 고유 ID 성격 값은 태그가 아닌 필드로 저장한다.
공식 · 구조
저장 용량 추정
용량 = 포인트 수 × 압축 후 바이트/포인트 , 포인트 수 = 태그 × 주파수 × 보존 기간(s)
시계열 압축(델타·Gorilla)은 통상 포인트당 1~3 B로 줄인다.
강의 연계 · 실습 · 사례
실습InfluxDB
1초 원시 데이터를 1분 평균으로 다운샘플링하는 작업을 설계하라
원시 버킷 보존 7일, 집계 태스크로 aggregateWindow(every: 1m, fn: mean) 결과를 장기 버킷(보존 2년)에 저장한다.
오해 · 함정
주의관계형 DB 단일 테이블에 고빈도 시계열을 저장하면 인덱스 갱신 부담으로 수집 지연이 발생한다.
5.2스트림 처리와 메시징★★★물데모서▶
핵심 정리
  • Apache Kafka는 분산 커밋 로그 기반 메시징으로, 토픽–파티션–오프셋 구조와 소비자 그룹으로 확장성과 재처리를 지원한다.
  • 스트림 처리 엔진(Apache Flink, Kafka Streams, Spark Structured Streaming)은 윈도우 집계, 상태 기반 처리, 복합 이벤트 처리(CEP)를 수행한다.
  • 윈도우 유형은 텀블링(고정·비중첩), 슬라이딩(중첩), 세션(비활동 간격 기준)이다.
  • 이벤트 시간(event time)과 처리 시간(processing time)을 구분하고, 워터마크(watermark)로 지연 도착 데이터를 처리한다.
  • 전송 보장 의미론은 at-most-once, at-least-once, exactly-once이며, 트윈 상태 갱신은 멱등(idempotent) 설계가 권장된다.
공식 · 구조
처리량 기준 파티션 수
파티션 수 ≥ max( 목표 처리량 / 생산자 파티션당 처리량 , 목표 처리량 / 소비자 파티션당 처리량 )
소비자 병렬도는 파티션 수를 초과할 수 없다.
강의 연계 · 실습 · 사례
실습Kafka + Flink
설비 온도 5분 이동평균 초과 시 경보를 발생시키는 파이프라인은?
Kafka 토픽 수신 → keyBy(설비ID) → 슬라이딩 윈도우(5분, 1분 간격) 평균 → 임계 비교 → 경보 토픽 발행이다.
오해 · 함정
주의처리 시간 기준 윈도우는 네트워크 지연 시 집계 결과가 달라진다. 트윈 분석은 이벤트 시간 기준이 원칙이다.
5.3데이터 레이크하우스와 데이터 플랫폼★★물데모서▶
핵심 정리
  • 레이크하우스는 데이터 레이크의 저비용 객체 저장소와 웨어하우스의 ACID·스키마 관리를 결합하며, Delta Lake·Apache Iceberg·Apache Hudi 테이블 포맷이 대표적이다.
  • 메달리온 아키텍처는 Bronze(원시) → Silver(정제·정합) → Gold(업무 집계) 단계로 데이터 품질을 높인다.
  • 열 지향 포맷(Parquet)은 시계열 분석 쿼리의 스캔 비용을 줄이며, 시간·설비 단위 파티셔닝이 효과적이다.
  • 데이터 메시(Data Mesh)는 도메인 소유·제품으로서의 데이터·셀프서비스 플랫폼·연합 거버넌스의 4원칙으로 대규모 조직의 트윈 데이터 관리에 적용된다.
공식 · 구조
메달리온 흐름
Bronze(원시 적재) → Silver(중복 제거·단위 통일·결측 처리) → Gold(KPI·특징값·학습 데이터셋)
AI 학습 데이터는 Gold 층에서 버전 관리한다.
강의 연계 · 실습 · 사례
설계데이터 플랫폼
트윈의 실시간 경로와 배치 경로를 통합하는 방식은?
람다(배치+속도 층 분리) 또는 카파(스트림 단일 경로 + 재처리) 아키텍처를 적용하며, 최근은 레이크하우스의 스트리밍 테이블로 단일화한다.
오해 · 함정
주의원시 데이터를 정제 과정에서 덮어쓰면 재현성이 사라진다. Bronze 층은 불변(immutable)으로 보존한다.
5.4데이터 품질과 전처리★★★물데모서▶
핵심 정리
  • 데이터 품질 차원은 정확성, 완전성, 일관성, 적시성, 유효성, 유일성이다.
  • 결측 처리: 짧은 결측은 선형 보간·전방 채움, 긴 결측은 모델 기반 대체(칼만 평활, 회귀)와 결측 표시 변수를 병행한다.
  • 이상값 탐지: 3σ 규칙, IQR(Q1−1.5IQR, Q3+1.5IQR), 해당 공정 물리 한계(rate-of-change 제한)를 적용한다.
  • 스케일 정규화: 최소-최대 정규화, 표준화(z-score), 로버스트 스케일링(중앙값·IQR)이 있다.
  • 센서 드리프트는 주기적 재교정 및 다중 센서 교차 검증(가상 센서 대비 잔차 모니터링)으로 탐지한다.
공식 · 구조
z-score
z = (x − μ) / σ , |z| > 3 이면 이상값 후보
정규분포 가정 시 |z|>3의 확률은 약 0.27%이다.
IQR 기준
하한 = Q1 − 1.5·IQR , 상한 = Q3 + 1.5·IQR (IQR = Q3 − Q1)
분포 가정이 필요 없는 로버스트 기준이다.
강의 연계 · 실습 · 사례
계산실습
Q1=20, Q3=30일 때 이상값 경계는?
IQR=10, 하한 5, 상한 45이다.
오해 · 함정
주의학습·검증 분할 전에 전체 데이터로 정규화 통계를 산출하면 정보 누설(data leakage)이 발생한다.
5.5지식 그래프와 시맨틱 데이터 통합★★물데모서▶
핵심 정리
  • 지식 그래프는 개체(노드)–관계(간선)–속성으로 설비 계층, 공정 흐름, 부품 BOM, 고장 이력을 연결하여 맥락 기반 질의를 가능하게 한다.
  • 속성 그래프(Neo4j, Cypher)와 RDF 트리플 저장소(SPARQL)가 대표적 구현 방식이다.
  • 트윈 그래프 질의 예: '구역 A의 냉각수 공급 펌프가 정지하면 영향을 받는 설비는?'과 같은 다단계 영향 분석이다.
  • 그래프 RAG는 지식 그래프를 LLM 검색 증강의 근거로 사용하여 다단계 추론 질의의 정확도를 높인다.
공식 · 구조
RDF 트리플
⟨주어, 술어, 목적어⟩ 예: ⟨Pump_01, feeds, Tank_03⟩
모든 사실을 트리플의 집합으로 표현한다.
강의 연계 · 실습 · 사례
실습Neo4j
영향 범위 분석 Cypher 질의를 작성하라
MATCH (p:Pump {id:'P01'})-[:FEEDS*1..3]->(e:Equipment) RETURN e.name — 최대 3단계 하류 설비를 조회한다.
오해 · 함정
주의시계열 원시값을 그래프 노드로 모두 적재하면 그래프 DB 성능이 급격히 저하된다. 그래프에는 관계·메타데이터, 시계열 DB에는 측정값을 둔다.

6.1CAD·BIM·GIS 데이터와 변환★★★물데모서▶
핵심 정리
  • 제조는 CAD(STEP AP242, JT, Parasolid), 건설은 BIM(IFC), 도시·국토는 GIS(Shapefile, GeoJSON, CityGML)가 원천 형상 데이터이다.
  • CAD의 B-rep(경계 표현) 솔리드는 실시간 렌더링을 위해 삼각형 메시로 테셀레이션(tessellation)해야 하며, 허용 오차(chord height)에 따라 폴리곤 수가 결정된다.
  • BIM은 형상과 함께 속성(재료, 공급사, 유지관리 정보)을 포함하여 시설 관리(FM) 트윈의 기반이 되며, COBie는 인계 정보 교환 규격이다.
  • CityGML LOD0~LOD4(3.0에서는 LOD0~3과 실내 분리) 단계로 도시 모델의 상세도를 정의한다.
공식 · 구조
테셀레이션 오차
chord error h ≈ r·(1 − cos(θ/2))
곡률 반경 r, 분할 각 θ가 작을수록 오차는 작고 폴리곤은 증가한다.
강의 연계 · 실습 · 사례
실습Unity Pixyz/Datasmith
CAD 조립품을 게임엔진에 임포트하는 절차는?
STEP 임포트 → 테셀레이션 품질 설정 → 숨은 부품 제거·병합 → LOD 생성 → 계층 구조(BOM) 유지 및 메타데이터 매핑이다.
오해 · 함정
주의설계용 CAD를 그대로 실시간 엔진에 넣으면 폴리곤 수천만 개로 프레임이 급락한다. 경량화 단계가 필수이다.
6.2좌표계와 동차 변환★★★물데모서▶
핵심 정리
  • 트윈은 월드 좌표계, 로컬(부모) 좌표계, 센서 좌표계, 지리 좌표계(WGS84 위경도, UTM, 국내 TM/GRS80) 간 변환을 다룬다.
  • 강체 변환은 회전 R(3×3 직교, det=1)과 평행이동 t로 구성되며, 4×4 동차 변환 행렬로 합성 연산을 행렬곱으로 표현한다.
  • 회전 표현은 오일러 각(짐벌 락 발생), 회전 행렬, 축-각, 쿼터니언(보간 SLERP 용이)이 있으며 게임엔진은 쿼터니언을 내부 표현으로 사용한다.
  • Unity는 왼손 좌표계 Y-up, Unreal은 왼손 Z-up, ROS·대부분 CAD는 오른손 Z-up이므로 축 변환이 필요하다.
  • 로봇 정기구학은 DH 파라미터로 링크 간 동차 변환을 연쇄 곱하여 말단 위치를 계산한다.
공식 · 구조
동차 변환
T = [ R t ; 0 1 ] , p' = T·p , T_AC = T_AB · T_BC
역변환 T⁻¹ = [ Rᵀ −Rᵀt ; 0 1 ]이다.
Z축 회전
R_z(θ) = [ cosθ −sinθ 0 ; sinθ cosθ 0 ; 0 0 1 ]
반시계 방향이 양의 각이다(오른손 좌표계).
쿼터니언
q = (cos(θ/2), u·sin(θ/2)) , p' = q p q*
단위축 u 기준 θ 회전이다.
강의 연계 · 실습 · 사례
계산실습
점 (1,0,0)을 Z축 90° 회전 후 (2,0,0) 평행이동하면?
회전 후 (0,1,0), 이동 후 (2,1,0)이다.
오해 · 함정
주의변환 합성 순서를 바꾸면 결과가 달라진다(행렬곱은 비가환). 회전 후 이동과 이동 후 회전을 구분한다.
6.3메시 최적화·LOD·렌더링★★물데모서▶
핵심 정리
  • 실시간 성능 지표는 프레임률(FPS), 드로우콜 수, 폴리곤 수, 텍스처 메모리이며, VR은 90 FPS 이상을 목표로 한다.
  • 최적화 기법은 LOD(거리별 상세도 전환), 오클루전 컬링, 인스턴싱(GPU instancing), 메시 결합, 텍스처 아틀라스, 베이크 라이팅이다.
  • 물리 기반 렌더링(PBR)은 알베도·금속성·거칠기·법선 맵으로 실제 재질의 반사 특성을 재현한다.
  • 실시간 레이트레이싱·경로 추적(Omniverse RTX, Unreal Lumen)은 센서 시뮬레이션(카메라·LiDAR)의 물리 정확도를 높인다.
  • Unreal Nanite 같은 가상화 지오메트리는 수십억 폴리곤을 자동 LOD로 스트리밍한다.
공식 · 구조
프레임 예산
프레임 시간(ms) = 1000 / FPS
60 FPS는 16.7 ms, 90 FPS는 11.1 ms 이내에 CPU·GPU 처리를 마쳐야 한다.
강의 연계 · 실습 · 사례
실습Unity
공장 라인 트윈의 드로우콜을 줄이는 방법 3가지를 쓰라
정적 배칭, GPU 인스턴싱(동일 설비 반복), 머티리얼·텍스처 아틀라스 통합이다.
오해 · 함정

공식 · 구조
USD 합성 우선순위
LIVRPS = Local > Inherits > VariantSets > References > Payloads > Specializes
강한 의견(opinion)이 약한 의견을 덮어쓴다.

6.5현실 캡처 — 포토그래메트리·LiDAR·NeRF·3D 가우시안 스플래팅★★★물데모서▶
핵심 정리
  • 포토그래메트리는 다시점 사진에서 SfM(Structure from Motion)으로 카메라 자세와 희소 점군을 복원하고, MVS로 조밀 점군·메시를 생성한다.
  • LiDAR는 비행시간(ToF)으로 거리를 측정하며, 지상형(TLS)·모바일(MLS)·항공(ALS) 스캐닝으로 점군을 획득하고 SLAM으로 정합한다.
  • 점군 정합은 ICP(Iterative Closest Point) 알고리즘으로 두 점군 간 강체 변환을 반복 추정한다.
  • NeRF(2020)는 신경망으로 공간의 밀도·색을 학습하여 새로운 시점을 합성하며, 3D 가우시안 스플래팅(3DGS, 2023)은 명시적 가우시안 집합을 래스터화하여 실시간 렌더링을 달성한다.
  • 3DGS 기반 현장 트윈은 촬영 수 시간 내 사실적 공간 재현이 가능하나, 편집성·측정 정확도·의미 정보 부족이 한계이다.
공식 · 구조
LiDAR 거리
d = c·Δt / 2
c ≈ 3×10⁸ m/s, Δt = 왕복 시간이다.
ICP 목적 함수
min_{R,t} Σᵢ ‖ R·pᵢ + t − qᵢ ‖²
대응점 갱신과 SVD 기반 변환 추정을 반복한다.
강의 연계 · 실습 · 사례
계산실습
LiDAR 왕복 시간이 200 ns이면 거리는?
3×10⁸ × 200×10⁻⁹ / 2 = 30 m이다.
오해 · 함정
주의NeRF·3DGS 결과는 시각적 사실성은 높으나 CAD 수준 치수 정확도를 보장하지 않는다. 계측 목적에는 기준점(GCP) 검증이 필요하다.

8.1동적 시스템 모델링 기초★★★물데모서▶
핵심 정리
  • 물리 기반 모델은 보존 법칙(질량·운동량·에너지)과 구성 방정식으로 미분방정식을 세워 시스템 거동을 예측한다.
  • 1차 시스템(열, RC 회로, 탱크 수위)은 시정수 τ, 2차 시스템(질량-스프링-댐퍼, 모터)은 고유진동수 ωₙ와 감쇠비 ζ로 특성화된다.
  • 기계·전기·열·유체 시스템은 노력(effort)–흐름(flow) 변수로 상사(analogy) 관계를 이룬다(본드 그래프).
  • 수치 적분은 오일러(1차), 룽게-쿠타 4차(RK4), 강성(stiff) 문제용 암시적 기법(BDF)을 사용하며 시간 간격이 안정성과 정확도를 좌우한다.
공식 · 구조
1차 시스템
τ·dy/dt + y = K·u , 계단응답 y(t) = K·u·(1 − e^(−t/τ))
t = τ에서 최종값의 63.2%, 4τ에서 98.2%에 도달한다.
2차 시스템
m·ẍ + c·ẋ + k·x = F , ωₙ = √(k/m) , ζ = c / (2√(mk))
ζ<1 부족감쇠, ζ=1 임계감쇠, ζ>1 과감쇠이다.
뉴턴 냉각
T(t) = T_∞ + (T₀ − T_∞)·e^(−t/τ) , τ = m·c_p / (h·A)
열 트윈의 가장 단순한 집중 질량 모델이다.
강의 연계 · 실습 · 사례
계산실습
시정수 10 s인 1차 시스템에 계단 입력(K·u=100) 후 20 s의 출력은?
100 × (1 − e⁻²) ≈ 86.5이다.
오해 · 함정
주의명시적 오일러 적분에서 시간 간격이 시정수에 비해 크면(Δt > 2τ) 수치 해가 발산한다.
8.2상태공간 모델과 시스템 식별★★★물데모서▶
핵심 정리
  • 상태공간 모델은 ẋ = Ax + Bu, y = Cx + Du로 다입출력 시스템을 표현하며 칼만 필터·MPC의 기본 형식이다.
  • 이산화는 x_{k+1} = A_d x_k + B_d u_k (A_d = e^{AΔt})로 수행한다.
  • 시스템 식별은 입출력 데이터로 모델 파라미터를 추정하는 기법이며, ARX·ARMAX·부분공간 식별(N4SID)·SINDy(희소 회귀 기반 방정식 발견)가 있다.
  • 가관측성(observability) 행렬의 계수가 상태 차원과 같아야 측정으로부터 전체 상태를 추정할 수 있다.
공식 · 구조
연속 상태공간
ẋ = A·x + B·u , y = C·x + D·u
전달함수 G(s) = C(sI − A)⁻¹B + D
가관측성
O = [ C ; CA ; CA² ; … ; CAⁿ⁻¹ ] , rank(O) = n
계수 부족 시 센서 추가 위치를 재검토한다.
ARX 모델
y_k = a₁y_{k−1} + … + b₁u_{k−1} + … + e_k
최소제곱으로 파라미터를 추정한다.
강의 연계 · 실습 · 사례
강의시스템 식별
실제 설비 데이터로 1차+지연(FOPDT) 모델을 식별하는 방법은?
계단 시험 데이터에서 정상상태 이득 K, 63.2% 도달 시간으로 τ, 응답 시작 지연으로 θ를 추정한다.
오해 · 함정
주의상관관계가 높은 입력만 있는 운전 데이터(폐루프 데이터)로 식별하면 파라미터가 편향된다. 여기(excitation) 신호가 필요하다.
8.3FMI·FMU와 Modelica★★★물데모서▶
핵심 정리
  • FMI(Functional Mock-up Interface)는 Modelica Association의 모델 교환 표준으로, 시뮬레이션 모델을 FMU(zip: XML 설명 + 바이너리/소스)로 패키징한다.
  • FMI 유형은 Model Exchange(적분기는 호스트 제공), Co-Simulation(FMU 자체 솔버 포함)이며, FMI 3.0(2022)은 Scheduled Execution, 배열·클록·바이너리 변수를 추가하였다.
  • Modelica는 방정식 기반(비인과적, acausal) 객체지향 모델링 언어로, 커넥터(across/through 변수)로 다중 물리 부품을 결합한다.
  • 도구로 OpenModelica, Dymola, Simulink(FMU 내보내기), Python FMPy가 있다.
  • SSP(System Structure and Parameterization)는 여러 FMU의 연결 구조를 기술하는 보완 표준이다.
공식 · 구조
Modelica 커넥터 규칙
연결점에서 across 변수 동일(e = e), through 변수 합 = 0(Σ f = 0)
키르히호프 법칙의 일반화이다.
강의 연계 · 실습 · 사례
실습FMPy
열교환기 FMU를 Python에서 실행하여 트윈 예측에 활용하는 절차는?
fmpy.simulate_fmu(파일, start_values=실측 초기값, input=운전 입력) → 결과를 실측과 비교 → 파라미터 보정이다.
오해 · 함정
주의Model Exchange FMU는 자체 솔버가 없으므로 호스트 적분기 설정이 필요하다. Co-Simulation FMU와 혼동하지 않는다.
8.4유한요소해석(FEM)·전산유체역학(CFD)★★물데모서▶
핵심 정리
  • FEM은 연속체를 요소로 분할하여 강성 행렬 방정식 K·u = F를 풀어 응력·변형·열전달을 해석한다.
  • CFD는 나비에-스토크스 방정식을 유한체적법(FVM)으로 이산화하며, 난류 모델(k-ε, k-ω SST, LES)을 선택한다.
  • 고충실도 해석은 수 시간~수 일이 걸려 실시간 트윈에 직접 사용하기 어려우므로, 축소차수모델·대리모델로 변환한다.
  • 메시 수렴성 검증(mesh independence)과 실험 검증(validation)이 해석 신뢰성의 전제이다.
  • GPU 가속 솔버와 AI 대리모델(뉴럴 오퍼레이터)이 실시간 CFD 트윈을 가능하게 하는 추세이다.
공식 · 구조
선형 정적 FEM
K·u = F , σ = D·B·u
K는 전체 강성 행렬, B는 변형률-변위 행렬, D는 재료 행렬이다.
레이놀즈수
Re = ρ·V·L / μ
관 유동은 Re ≈ 2300 이상에서 난류 천이가 시작된다.
강의 연계 · 실습 · 사례
사례데이터센터
CFD 기반 냉각 트윈의 운영 방식은?
오프라인 CFD 다수 케이스로 대리모델 학습 → 실시간 온도 센서로 보정 → 공조 설정 변경 시 온도장 예측 → 에너지 최적 설정 추천이다.
오해 · 함정
주의메시 수렴성 검증 없이 CFD 결과를 트윈 기준값으로 사용하면 체계적 오차가 누적된다.
8.5축소차수모델(ROM)과 다중 충실도★★★물데모서▶
핵심 정리
  • ROM은 고차원 모델(수백만 자유도)을 소수 모드로 근사하여 실시간 계산을 가능하게 한다.
  • POD(Proper Orthogonal Decomposition)는 스냅숏 행렬의 SVD로 에너지 기준 주요 모드를 추출하며, 갤러킨 투영으로 축소 방정식을 얻는다.
  • DMD(Dynamic Mode Decomposition)는 시계열 스냅숏에서 선형 동역학 모드와 고유값(성장률·진동수)을 추출한다.
  • 다중 충실도 모델링은 저충실도(빠름)와 고충실도(정확) 결과를 코크리깅 등으로 결합하여 비용 대비 정확도를 최적화한다.
  • 상용 도구(Ansys Twin Builder, Simcenter ROM Builder)는 FMU 형태 ROM을 생성하여 운영 트윈에 탑재한다.
공식 · 구조
POD
X = U·Σ·Vᵀ , 에너지 비율 = Σᵢ₌₁ʳ σᵢ² / Σ σᵢ² ≥ 99% 가 되는 r 선택
x ≈ U_r·a(t) 로 근사한다.
DMD
X' ≈ A·X , A ≈ X'·X⁺ , 고유값 λ → 연속 ω = ln(λ)/Δt
실수부는 성장/감쇠율, 허수부는 진동수이다.
강의 연계 · 실습 · 사례
강의ROM
POD 모드 수 선택 기준은?
특이값 에너지 누적 비율(예: 99%) 또는 검증 오차 허용치를 만족하는 최소 r을 선택한다.
오해 · 함정
주의ROM은 학습(스냅숏) 범위 밖의 운전 조건에서 정확도가 급격히 떨어진다. 적용 범위(validity domain)를 명시한다.

시뮬레이션 기법

이산사건·에이전트·시스템다이내믹스·몬테카를로·가상 시운전
9.1이산사건 시뮬레이션(DES)과 대기행렬★★★물데모서▶
핵심 정리
  • DES는 상태가 이산 시점의 사건(도착·서비스 시작·완료)에서만 변화하는 시스템을 사건 목록(future event list)으로 모사한다.
  • 생산 라인·물류센터·병원 대기 등 자원 경쟁 시스템의 처리량·대기시간·가동률 분석에 사용한다.
  • 대기행렬 이론의 켄달 표기 A/B/c/K는 도착 분포/서비스 분포/서버 수/용량이며, M은 지수분포(포아송 도착)를 뜻한다.
  • 리틀의 법칙 L = λW는 분포 가정 없이 안정 상태 시스템에 성립한다.
  • 도구로 AnyLogic, Siemens Plant Simulation, FlexSim, Arena, Python SimPy가 있다.
공식 · 구조
M/M/1
ρ = λ/μ , L = ρ/(1 − ρ) , W = 1/(μ − λ) , L_q = ρ²/(1 − ρ) , W_q = ρ/(μ − λ)
ρ < 1 이어야 안정하다.
리틀의 법칙
L = λ·W
재공재고(WIP) = 처리율 × 리드타임 (공장 물리학)
강의 연계 · 실습 · 사례
계산실습
도착률 8개/h, 처리율 10개/h인 M/M/1 공정의 평균 체류시간은?
W = 1/(10−8) = 0.5 h, L = 4개, ρ = 0.8이다.
오해 · 함정
주의가동률을 100%에 가깝게 설계하면 대기 시간이 1/(1−ρ)로 폭증한다. 병목 공정은 여유 용량이 필요하다.
9.2에이전트 기반 모델링과 시스템 다이내믹스★★물데모서▶
핵심 정리
  • 에이전트 기반 모델링(ABM)은 개별 개체(사람·차량·로봇)의 규칙과 상호작용으로부터 전체 현상(창발)을 모사한다.
  • 시스템 다이내믹스(SD)는 저량(stock)–유량(flow)–피드백 루프로 장기·집계 수준의 동태(공급망 채찍효과, 인구, 정책)를 모사한다.
  • 다중 방법론(Multi-method) 시뮬레이션은 DES·ABM·SD를 계층적으로 결합하며 AnyLogic이 대표 도구이다.
  • 도시 트윈의 교통(MATSim, SUMO), 보행·대피 시뮬레이션은 ABM의 주요 응용이다.
공식 · 구조
저량-유량
Stock(t) = Stock(t₀) + ∫ (유입 − 유출) dt
강화 루프(+)는 성장, 균형 루프(−)는 목표 수렴을 만든다.
강의 연계 · 실습 · 사례
사례공급망
채찍효과(bullwhip effect)를 SD로 설명하라
수요 정보 지연과 단계별 안전재고 보정 정책이 결합되어 상류로 갈수록 주문 변동이 증폭된다.
오해 · 함정
주의ABM은 파라미터가 많아 보정 없이 사용하면 결과가 그럴듯하나 검증되지 않은 '이야기'가 될 수 있다.
9.3몬테카를로와 불확실성 전파★★물데모서▶
핵심 정리
  • 몬테카를로 시뮬레이션은 입력 확률분포에서 표본을 반복 추출하여 출력 분포를 추정한다.
  • 추정 오차는 표본 수 N에 대해 1/√N로 감소하며, 라틴 하이퍼큐브 표본(LHS)·준난수(Sobol)로 효율을 높인다.
  • 시뮬레이션 출력 분석은 워밍업 기간 제거, 반복(replication) 기반 신뢰구간, 공통 난수(CRN)를 이용한 대안 비교를 수행한다.
  • 민감도 분석은 국소(편미분)와 전역(Sobol 지수, Morris 법) 방식이 있다.
공식 · 구조
몬테카를로 표준오차
SE = s / √N , 95% CI = x̄ ± 1.96·SE
오차를 절반으로 줄이려면 표본을 4배 늘려야 한다.
Sobol 1차 지수
Sᵢ = Var(E[Y|Xᵢ]) / Var(Y)
입력 Xᵢ 단독이 설명하는 출력 분산 비율이다.
강의 연계 · 실습 · 사례
계산실습
N=100에서 표준편차 20이면 평균의 95% 신뢰구간 반폭은?
1.96 × 20/10 = 3.92이다.
오해 · 함정
주의시뮬레이션을 1회 실행한 결과로 대안을 비교하는 것은 통계적으로 무의미하다. 다회 반복과 신뢰구간 비교가 필요하다.
9.4공동 시뮬레이션과 시뮬레이션 연동★★물데모서▶
핵심 정리
  • 공동 시뮬레이션(co-simulation)은 서로 다른 도구의 모델(기계·전기·제어·통신)을 마스터 알고리즘이 통신 시점마다 데이터 교환하며 결합 실행한다.
  • 교환 방식은 Jacobi(병렬, 같은 시점 값 사용)와 Gauss-Seidel(순차, 갱신값 즉시 사용)이며 통신 간격이 정확도·안정성을 좌우한다.
  • HLA(IEEE 1516)는 분산 시뮬레이션 상호운용 표준으로 국방·항공 분야에서 사용되며, DDS(Data Distribution Service)는 ROS 2·자율시스템 실시간 미들웨어이다.
  • MIL(Model-in-the-loop) → SIL(Software) → PIL(Processor) → HIL(Hardware-in-the-loop) 순으로 실제성을 높여 검증한다.
공식 · 구조
X-in-the-loop 단계
MIL → SIL → PIL → HIL → 실차/실설비
뒤로 갈수록 실제성↑, 비용↑, 실시간성 요구↑이다.
강의 연계 · 실습 · 사례
강의HIL
HIL 시험에서 트윈의 역할은?
실제 제어기에 연결된 실시간 플랜트 모델로서 위험·고비용 시나리오(고장 주입)를 반복 시험하게 한다.
오해 · 함정
주의공동 시뮬레이션의 통신 간격을 크게 잡으면 대수 루프·지연으로 인해 결합 시스템이 불안정해질 수 있다.
9.5가상 시운전(Virtual Commissioning)★★★물데모서▶
핵심 정리
  • 가상 시운전은 실제 PLC/로봇 제어기(또는 에뮬레이터)를 3D 기구·물리 모델에 연결하여 설치 전 제어 로직을 검증하는 기법이다.
  • 구성은 제어 모델(PLCSIM, 가상 로봇 컨트롤러), 설비 거동 모델(센서·액추에이터·물류), 시각화 모델이며, 신호 매핑 테이블이 핵심 산출물이다.
  • 도구로 Siemens Process Simulate·NX MCD, Rockwell Emulate3D, ISG-virtuos, Visual Components가 있다.
  • 효과는 현장 시운전 기간 단축, 결함 조기 발견, 운전자 사전 교육이며, 개조(brownfield) 라인 변경 검증에도 적용된다.
공식 · 구조
신호 매핑
PLC 출력(Q) → 가상 액추에이터 , 가상 센서 → PLC 입력(I)
I/O 수 × 사이클 타임이 실시간 성능 요구를 결정한다.
강의 연계 · 실습 · 사례
강의가상 시운전
가상 시운전 수준을 구분하라
소프트웨어 인 더 루프(가상 PLC+가상 설비)와 하드웨어 인 더 루프(실제 PLC+가상 설비)로 구분한다.
오해 · 함정
주의가상 시운전이 현장 시운전을 완전히 대체하지는 않는다. 배선·센서 정렬·실물 마찰 등은 현장 검증이 필요하다.
제10편

상태 추정과 트윈 동기화

칼만 필터·파티클 필터·데이터 동화·모델 보정·UQ
10.1칼만 필터★★★물데모서▶
핵심 정리
  • 칼만 필터는 선형-가우시안 시스템에서 예측(모델)과 측정(센서)을 오차 공분산 기반으로 최적 결합하는 재귀적 상태 추정기이다.
  • 예측 단계에서 상태와 공분산을 전파하고, 갱신 단계에서 칼만 이득으로 측정 잔차를 반영한다.
  • Q(공정 잡음)가 크면 측정을 더 신뢰하고, R(측정 잡음)이 크면 모델을 더 신뢰한다.
  • 트윈에서 칼만 필터는 잡음 제거, 측정되지 않는 상태(가상 센서) 추정, 센서 융합(IMU+GPS)에 사용된다.
공식 · 구조
예측
x̂⁻ₖ = A·x̂ₖ₋₁ + B·uₖ , P⁻ₖ = A·Pₖ₋₁·Aᵀ + Q
모델로 상태와 불확실성을 전파한다.
갱신
Kₖ = P⁻ₖCᵀ(CP⁻ₖCᵀ + R)⁻¹ , x̂ₖ = x̂⁻ₖ + Kₖ(yₖ − Cx̂⁻ₖ) , Pₖ = (I − KₖC)P⁻ₖ
1차원이면 K = P⁻/(P⁻ + R)이다.
강의 연계 · 실습 · 사례
계산실습
1차원에서 P⁻=4, R=1, 예측 10, 측정 12이면 추정값은?
K = 4/5 = 0.8, x̂ = 10 + 0.8×2 = 11.6, P = 0.8이다.
오해 · 함정
주의칼만 필터는 선형 가우시안 가정에서 최적이다. 강한 비선형 시스템에는 EKF·UKF·파티클 필터를 사용한다.
10.2비선형 필터 — EKF·UKF·파티클 필터★★물데모서▶
핵심 정리
  • EKF는 비선형 함수를 현재 추정점에서 1차 테일러 전개(야코비안)하여 칼만 필터를 적용한다.
  • UKF는 시그마 포인트(2n+1개)를 비선형 함수에 통과시켜 평균·공분산을 근사하며 야코비안이 필요 없다.
  • 파티클 필터(순차 몬테카를로)는 가중치를 가진 표본 집합으로 임의 분포를 표현하며, 다봉 분포·비가우시안에 적합하다.
  • 파티클 필터는 가중치 퇴화(degeneracy)를 막기 위해 유효 표본 수가 임계 이하일 때 재표본(resampling)을 수행한다.
공식 · 구조
EKF 선형화
Fₖ = ∂f/∂x |_(x̂ₖ₋₁) , Hₖ = ∂h/∂x |_(x̂⁻ₖ)
이후 표준 칼만 식에 대입한다.
유효 표본 수
N_eff = 1 / Σ wᵢ²
N_eff < N/2 이면 재표본한다.

10.3데이터 동화★★물데모서▶
핵심 정리
  • 데이터 동화(Data Assimilation)는 대규모 수치 모델(기상·해양·지하수)의 상태를 관측으로 보정하는 기법이며, 디지털 트윈 동기화의 이론적 기반이다.
  • 순차 방식(EnKF: 앙상블로 공분산 추정)과 변분 방식(3D-Var, 4D-Var: 비용함수 최소화)으로 구분한다.
  • 4D-Var는 시간 창 전체의 관측을 동시에 반영하며 수치예보 현업에서 사용된다.
  • 최근 AI 기상 모델(GraphCast, Pangu-Weather 등)과 데이터 동화의 결합, 미분 가능 시뮬레이터 기반 동화가 연구되고 있다.

J(x) = ½(x − x_b)ᵀB⁻¹(x − x_b) + ½(y − Hx)ᵀR⁻¹(y − Hx)

  • 결정론적 방법은 최소제곱 최적화(Levenberg-Marquardt), 확률적 방법은 베이지안 추론(MCMC, 근사 베이지안 계산)이다.
  • Kennedy-O'Hagan 프레임워크는 관측 = 모델(θ) + 모델 불일치 δ(x) + 측정오차로 분해하여 모델 구조 오차를 명시적으로 다룬다.
  • 운영 중 열화로 파라미터가 변하므로 온라인 보정(재귀 최소제곱, 상태 증강 칼만 필터)을 적용한다.

11.1시계열 예측 모델★★★물데모서▶
핵심 정리
  • 통계 모델은 ARIMA(자기회귀·차분·이동평균), SARIMA(계절성), 지수평활(Holt-Winters), 상태공간 모델이다.
  • 딥러닝 모델은 LSTM·GRU(게이트 순환), TCN(팽창 인과 합성곱), Transformer 계열(Informer, PatchTST, iTransformer)이며, 선형 모델(DLinear)이 강력한 기준선임이 보고되었다.
  • 시계열 기반 모델(Foundation model)로 TimesFM, Chronos, Moirai, Lag-Llama 등이 등장하여 제로샷 예측이 가능해졌다.
  • 평가 지표는 MAE, RMSE, MAPE, sMAPE, MASE이며, 시간 순서를 보존하는 롤링(walk-forward) 검증을 사용한다.
  • 다중 시점 예측 전략은 재귀(recursive), 직접(direct), 다중 출력(MIMO) 방식이 있다.

지표

f = σ(W_f[h,x]+b_f), i = σ(·), o = σ(·), c̃ = tanh(·), c = f⊙c₋₁ + i⊙c̃, h = o⊙tanh(c)

11.2이상 탐지★★★물데모서▶
핵심 정리
  • 이상 유형은 점 이상(spike), 맥락 이상(정상 범위이나 상황상 비정상), 집단 이상(패턴 이상)이다.
  • 통계 기법(관리도, 마할라노비스 거리, Hotelling T², PCA Q통계량), 머신러닝(Isolation Forest, One-Class SVM, LOF), 딥러닝(오토인코더, LSTM-AE, USAD, Anomaly Transformer)이 사용된다.
  • 재구성 기반 탐지는 정상 데이터로 학습한 오토인코더의 재구성 오차가 임계값을 초과하면 이상으로 판정한다.
  • 트윈 기반 잔차 탐지는 물리 모델 예측값과 측정값의 잔차를 감시하여 해석 가능성이 높다.
  • 레이블이 희소하므로 비지도·준지도 학습이 기본이며, 임계값은 검증 데이터의 백분위수 또는 극단값 이론(EVT)으로 설정한다.
공식 · 구조

D² = (x − μ)ᵀ Σ⁻¹ (x − μ)
변수 간 상관을 반영한 다변량 거리이다.
관리도 (Shewhart)
UCL = μ + 3σ , LCL = μ − 3σ

재구성 오차
e = ‖x − D(E(x))‖² , e > τ → 이상
τ는 정상 검증 데이터 오차의 99 백분위수 등으로 정한다.

오해 · 함정

11.3물리 정보 신경망(PINN)과 뉴럴 오퍼레이터★★★물데모서▶
핵심 정리
  • PINN은 지배 방정식 잔차를 손실 함수에 포함하여 데이터가 적어도 물리 법칙을 만족하는 해를 학습하며, 자동미분으로 편미분을 계산한다.
  • 역문제(미지 파라미터 추정)에 강점이 있으나, 강성·다중 스케일 문제에서 학습이 어렵고 손실 가중치 조정이 필요하다.
  • 뉴럴 오퍼레이터는 함수 공간 간 사상(입력 조건 → 해 필드)을 학습하며, FNO(푸리에 뉴럴 오퍼레이터)와 DeepONet(분기망·줄기망)이 대표적이다.
  • 학습 후 새로운 조건의 해를 밀리초 단위로 추론하여 CFD·FEM의 실시간 대리모델로 사용한다(예: NVIDIA PhysicsNeMo/Modulus).
  • 그래프 기반 메시 학습(MeshGraphNets)은 비정형 메시 위의 물리 시뮬레이션을 학습한다.

v_{l+1}(x) = σ( W·v_l(x) + 𝓕⁻¹( R_φ · 𝓕(v_l) )(x) )
저주파 푸리에 모드에서 학습된 가중치를 곱한다.

11.4그래프 신경망과 공간-시간 모델★★물데모서▶
핵심 정리
  • GNN은 노드–간선 구조 데이터에서 메시지 전달로 표현을 학습하며, 설비 네트워크·전력망·상하수도·교통망 트윈에 적합하다.
  • GCN, GraphSAGE, GAT(주의 기반)가 대표적이며, 시공간 GNN(STGCN, DCRNN, Graph WaveNet)은 교통 흐름 예측의 표준 모델이다.
  • 공정 간 인과 관계를 그래프로 학습하면 근본 원인 분석(RCA)과 고장 전파 경로 추정이 가능하다.
  • 지식 그래프 임베딩(TransE 등)은 트윈 메타데이터 간 관계 추론에 사용된다.

메시지 전달
h_v^(l+1) = σ( W·AGG{ h_u^(l) : u ∈ N(v) } + B·h_v^(l) )

11.5하이브리드 모델과 대리모델★★★물데모서▶
핵심 정리
  • 하이브리드(그레이박스) 모델은 물리 모델과 데이터 모델을 결합하여 해석 가능성과 정확도를 함께 확보한다.
  • 결합 방식은 직렬(물리 모델 입력·출력 보정), 병렬(물리 예측 + 잔차 학습), 내장(미지 항만 신경망으로 대체, 예: Universal Differential Equation)이다.
  • 대리모델(Surrogate)은 고비용 시뮬레이션의 입출력 관계를 가우시안 과정(크리깅), RBF, 다항식, 신경망으로 근사한다.
  • 능동 학습·베이지안 최적화는 대리모델의 불확실성이 큰 지점을 추가 시뮬레이션하여 표본 효율을 높인다.
  • 미분 가능 시뮬레이션(JAX, Warp)은 물리 시뮬레이터를 신경망과 함께 경사 기반으로 학습·보정할 수 있게 한다.
공식 · 구조
잔차 학습 하이브리드
ŷ = f_phys(x; θ) + g_NN(x) , g_NN은 (y − f_phys) 를 학습
데이터가 적은 영역에서도 물리 모델이 기본값을 제공한다.
가우시안 과정
f ~ GP(m(x), k(x,x')) , k_RBF = σ²·exp(−‖x − x'‖²/(2ℓ²))
예측 평균과 분산을 함께 제공한다.
강의 연계 · 실습 · 사례
강의대리모델
대리모델 구축 절차는?
실험계획(LHS)으로 입력 표본 생성 → 고충실도 시뮬레이션 실행 → 대리모델 학습 → 교차검증 → 오차 큰 영역 능동 표본 추가이다.
오해 · 함정
주의순수 데이터 모델은 학습 범위 외삽에 취약하다. 극한 조건 예측에는 물리 제약이 있는 하이브리드가 안전하다.

12.1보전 전략과 PHM 체계★★★물데모서▶
핵심 정리
  • 보전 전략은 사후보전(고장 후 수리) → 예방보전(시간 기준, TBM) → 상태기반보전(CBM) → 예지보전(PdM, 고장 시점 예측) → 처방보전(최적 조치 권고)으로 진화한다.
  • PHM(Prognostics and Health Management)은 데이터 획득 → 신호처리·특징 추출 → 상태 진단 → 예지(RUL 추정) → 의사결정의 단계로 구성된다(ISO 13374 OSA-CBM).
  • P-F 곡선은 잠재 고장 탐지 시점(P)부터 기능 고장(F)까지의 간격으로, 점검 주기는 P-F 간격보다 짧아야 한다.
  • 신뢰성 중심 보전(RCM)과 FMEA는 고장 모드별 위험 우선순위(RPN)로 보전 대상을 선정한다.
공식 · 구조
RPN
RPN = 심각도(S) × 발생도(O) × 검출도(D) (각 1~10)
최근 AIAG-VDA FMEA는 조치 우선순위(AP) 표를 사용한다.
P-F 간격
점검 주기 ≤ (P-F 간격) / 2 (통상 기준)
연속 모니터링은 P 시점 탐지를 앞당긴다.
강의 연계 · 실습 · 사례
강의PHM
ISO 13374 OSA-CBM의 6개 블록을 쓰라
데이터 획득, 데이터 처리, 상태 감지, 건전성 평가, 예지 평가, 권고 생성이다.
오해 · 함정
주의예지보전을 모든 설비에 적용하는 것은 비효율적이다. 중요도·고장 영향 분석으로 적용 대상을 선별한다.
12.2진동 분석과 특징 추출★★★물데모서▶
핵심 정리
  • 회전기계 진단의 핵심은 진동이며, 시간 영역 특징(RMS, 피크, 파고율, 첨도, 왜도)과 주파수 영역 특징(FFT 스펙트럼, 대역 에너지)을 추출한다.
  • 불평형은 1X(회전 주파수), 축 정렬 불량은 2X, 기계적 풀림은 다수 고조파, 베어링 결함은 결함 주파수(BPFO, BPFI, BSF, FTF)에서 나타난다.
  • 포락선 분석(엔벨로프, 힐베르트 변환)은 고주파 공진에 변조된 베어링 충격 성분을 검출한다.
  • 비정상 신호에는 STFT, 웨이블릿 변환, 스펙트로그램을 사용하며, 이를 이미지로 CNN에 입력하는 방식도 쓰인다.
  • ISO 10816/20816은 설비 등급별 진동 속도 RMS 기준(구역 A~D)을 제시한다.
공식 · 구조
FFT 주파수 분해능
Δf = fₛ / N
N 포인트 FFT의 최대 분석 주파수는 fₛ/2이다.
시간 영역 특징
RMS = √(Σx²/N) , 파고율 CF = |x|_peak / RMS , 첨도 = E[(x − μ)⁴]/σ⁴
정규분포 첨도는 3이며 충격성 결함 시 증가한다.
베어링 외륜 결함 주파수
BPFO = (n/2)·f_r·(1 − (d/D)·cosα)
n 볼 수, d 볼 직경, D 피치 직경, α 접촉각이다.
강의 연계 · 실습 · 사례
계산실습
fₛ = 10 240 Hz, N = 4096일 때 주파수 분해능은?
Δf = 2.5 Hz이다.
오해 · 함정
주의첨도는 결함 초기에 증가하나 결함이 진전되면 다시 감소할 수 있다. 단일 특징값 추세만으로 판단하지 않는다.
12.3잔존 유효 수명(RUL) 예측★★★물데모서▶
핵심 정리
  • RUL은 현재 시점부터 기능 고장까지 남은 시간이며, 건전성 지표(HI)의 열화 궤적을 고장 임계값까지 외삽하여 추정한다.
  • 접근법은 물리 기반(균열 성장 Paris 법칙), 데이터 기반(회귀·LSTM·CNN), 확률 기반(와이블·감마·위너 과정), 하이브리드가 있다.
  • NASA C-MAPSS(터보팬 엔진) 데이터셋이 RUL 연구의 대표 벤치마크이며, 구간 선형(piecewise linear) RUL 레이블을 사용한다.
  • RUL은 점추정과 함께 신뢰구간으로 제공해야 하며, 조기 예측보다 늦은 예측에 더 큰 벌점을 주는 비대칭 점수를 사용한다.
공식 · 구조
선형 열화 외삽
HI(t) = a + b·t , RUL = (HI_th − HI(t_now)) / b
지수 열화는 HI = a·e^(bt)로 모형화한다.
Paris 법칙
da/dN = C·(ΔK)ᵐ
균열 길이 a, 응력확대계수 범위 ΔK이다.
C-MAPSS 점수
s = Σ (e^(−d/13) − 1) [d<0] , Σ (e^(d/10) − 1) [d≥0] , d = 예측 − 실제
늦은 예측에 더 큰 벌점을 준다.
강의 연계 · 실습 · 사례
계산실습
HI가 현재 0.6, 열화율 0.01/일, 임계 0.9이면 RUL은?
(0.9 − 0.6)/0.01 = 30일이다.
오해 · 함정
주의운전 조건(부하·속도)이 바뀌면 열화율도 변한다. 조건 정규화 없이 단일 기울기로 외삽하면 오차가 크다.
12.4신뢰성 지표와 와이블 분석★★★물데모서▶
핵심 정리
  • 신뢰도 R(t)는 t까지 고장 없이 작동할 확률이며, 고장률 h(t) = f(t)/R(t)이다.
  • 욕조 곡선은 초기 고장(감소 고장률) → 우발 고장(일정) → 마모 고장(증가) 구간으로 구성된다.
  • 와이블 분포의 형상모수 β<1은 초기 고장, β=1은 지수분포(우발 고장), β>1은 마모 고장을 의미한다.
  • 가용도(Availability)는 MTBF/(MTBF+MTTR)이며, 직렬 시스템 신뢰도는 곱, 병렬 시스템은 1 − Π(1 − Rᵢ)이다.
공식 · 구조
와이블
R(t) = exp(−(t/η)^β) , h(t) = (β/η)(t/η)^(β−1)
η는 척도모수(특성 수명, R=36.8% 시점)이다.
가용도
A = MTBF / (MTBF + MTTR)
지수분포에서 MTBF = 1/λ이다.
직·병렬 신뢰도
R_직렬 = Π Rᵢ , R_병렬 = 1 − Π(1 − Rᵢ)
이중화는 병렬 구조로 신뢰도를 높인다.
강의 연계 · 실습 · 사례
계산실습
MTBF 950 h, MTTR 50 h이면 가용도는?
950/1000 = 0.95(95%)이다.
오해 · 함정
주의β=1인 지수분포에서는 예방 교체가 신뢰도를 높이지 못한다(무기억성). 마모(β>1) 부품에만 예방 교체가 유효하다.
12.5OEE와 생산 성과 지표★★물데모서▶
핵심 정리
  • OEE(설비종합효율) = 가용률 × 성능률 × 품질률이며, 세계 수준은 통상 85%로 언급된다.
  • 6대 손실은 고장, 준비·조정(가용률), 순간 정지, 속도 저하(성능률), 공정 불량, 초기 수율 손실(품질률)이다.
  • 트윈은 OEE 손실을 실시간으로 분해·원인 추적하고, 개선안을 시뮬레이션으로 사전 평가한다.
  • 에너지 트윈은 에너지 원단위(제품당 kWh)와 탄소 배출(Scope 1·2·3)을 공정 단위로 추적하여 ESG 공시를 지원한다.
공식 · 구조
OEE
OEE = (가동시간/계획시간) × (이상 사이클×생산량/가동시간) × (양품/생산량)
세 비율의 곱이다.
강의 연계 · 실습 · 사례
계산실습
가용률 90%, 성능률 95%, 품질률 99%이면 OEE는?
0.9 × 0.95 × 0.99 ≈ 84.6%이다.
오해 · 함정
주의계획 정지(휴식·예방보전)를 계획시간에 포함할지 여부에 따라 OEE가 달라진다. 정의를 명확히 한다.

13.1PID 제어와 튜닝★★★물데모서▶
핵심 정리
  • PID 제어기는 오차의 비례(현재), 적분(과거 누적, 정상상태 오차 제거), 미분(미래 경향, 오버슈트 억제)을 결합한다.
  • 튜닝 방법은 지글러-니콜스(한계 감도·계단 응답), Cohen-Coon, IMC/λ 튜닝, 트윈 기반 자동 튜닝이다.
  • 적분 와인드업(액추에이터 포화 시 적분 누적)은 anti-windup(클램핑, 역계산)으로 방지한다.
  • 트윈에서 제어 파라미터를 사전 튜닝·검증한 뒤 실설비에 적용하면 시운전 위험을 줄일 수 있다.
공식 · 구조
PID
u(t) = K_p·e(t) + K_i∫e dt + K_d·de/dt
이산형 uₖ = K_p eₖ + K_i T Σe + K_d (eₖ − eₖ₋₁)/T
지글러-니콜스 (한계 감도법)
K_p = 0.6K_u , T_i = 0.5P_u , T_d = 0.125P_u
K_u 한계 이득, P_u 한계 진동 주기이다.
강의 연계 · 실습 · 사례
실습트윈 튜닝
1차+지연 모델(K=2, τ=10 s, θ=2 s)에 대한 λ 튜닝 PI 값은?
λ=τ로 두면 K_p = τ/(K(λ+θ)) = 10/(2×12) ≈ 0.42, T_i = τ = 10 s이다.
오해 · 함정
주의미분항은 측정 잡음을 증폭한다. 미분 필터를 두거나 오차 대신 측정값 미분(derivative on measurement)을 사용한다.
13.2모델 예측 제어(MPC)★★★물데모서▶
핵심 정리
  • MPC는 트윈(예측 모델)으로 미래 예측 구간의 출력을 예측하고, 제약 조건 하에서 비용함수를 최소화하는 입력 열을 매 주기 최적화한다(후퇴 구간 방식).
  • 첫 입력만 적용하고 다음 주기에 다시 최적화하므로 외란과 모델 오차에 피드백 보정이 이루어진다.
  • 공정 산업(정유·화학)에서 다변수 제약 제어의 표준이며, 건물 HVAC·배터리·자율주행으로 확장되었다.
  • 비선형 MPC, 경제적 MPC(비용 직접 최적화), 학습 기반 MPC(신경망 예측 모델)가 최신 동향이다.
공식 · 구조
MPC 비용함수
min_u Σₖ₌₁ᴺᵖ ‖yₖ − r‖²_Q + Σₖ₌₀ᴺᶜ⁻¹ ‖Δuₖ‖²_R s.t. u_min ≤ u ≤ u_max, y_min ≤ y ≤ y_max

강의 연계 · 실습 · 사례
사례빌딩 트윈
건물 냉방 MPC의 에너지 절감 원리는?
기상 예보와 재실 예측을 반영하여 전기요금이 낮은 시간에 예냉(건물 열용량 활용)하고 피크 시간 부하를 이동시킨다.
오해 · 함정
주의MPC 성능은 예측 모델 정확도에 의존한다. 모델 불일치가 크면 제약 위반이나 성능 저하가 발생한다.
13.3강화학습과 Sim-to-Real★★★물데모서▶
핵심 정리
  • 강화학습은 마르코프 결정 과정(MDP)에서 누적 보상을 최대화하는 정책을 학습하며, 트윈은 안전하고 무한 반복 가능한 학습 환경이다.
  • 대표 알고리즘은 DQN(가치 기반), PPO·SAC(정책 경사·액터-크리틱)이며, 연속 제어에는 PPO·SAC가 주로 쓰인다.
  • Sim-to-Real 격차 해소 기법은 도메인 랜덤화(물리 파라미터·시각 요소 무작위화), 시스템 식별 정밀화, 도메인 적응, 실환경 미세조정이다.
  • 오프라인 강화학습(CQL, IQL)은 기존 운전 로그만으로 정책을 학습하여 탐색 위험을 줄인다.
  • 대규모 GPU 병렬 시뮬레이션(Isaac Lab, MuJoCo MJX)으로 수천 개 환경을 동시 학습한다.
공식 · 구조
벨만 최적 방정식
Q*(s,a) = E[ r + γ·max_a' Q*(s',a') ]
γ는 할인율이다.
PPO 클리핑 목적
L = E[ min( r_t(θ)Â_t , clip(r_t(θ), 1−ε, 1+ε)Â_t ) ]
정책 갱신 폭을 제한하여 학습을 안정화한다.
강의 연계 · 실습 · 사례
강의Isaac Lab
로봇 파지 정책을 트윈에서 학습해 실기에 이전하는 절차는?
로봇·물체 USD 구성 → 마찰·질량·조명 랜덤화 → PPO 병렬 학습 → 시뮬 내 검증 → 실기 소량 미세조정·안전 모니터링 하 배포이다.
오해 · 함정
주의보상 함수 설계 오류는 의도치 않은 편법 행동(reward hacking)을 유발한다. 시뮬에서 행동을 시각적으로 검증한다.
13.4최적화와 생산 스케줄링★★물데모서▶
핵심 정리
  • 트윈 최적화는 결정 변수, 목적함수, 제약을 정의한 수리 최적화(LP·MILP)와 시뮬레이션 기반 최적화(SBO)로 구분된다.
  • 생산 스케줄링은 잡숍·플로우숍 문제(NP-hard)이며, 디스패칭 규칙(SPT, EDD), 메타휴리스틱(GA, SA, 타부 탐색), 제약 프로그래밍, 강화학습이 사용된다.
  • 다목적 최적화는 파레토 최적해 집합을 구하며 NSGA-II가 대표 알고리즘이다.
  • 베이지안 최적화는 평가 비용이 큰 시뮬레이션 파라미터 최적화에 적합하다(획득함수 EI, UCB).
공식 · 구조
파레토 지배
x가 y를 지배 ⇔ ∀i fᵢ(x) ≤ fᵢ(y) ∧ ∃j fⱼ(x) < fⱼ(y)
지배되지 않는 해의 집합이 파레토 전선이다.
기대 개선 (EI)
EI(x) = E[ max(0, f_best − f(x)) ]
탐색(불확실성)과 활용(평균)을 균형한다.

  • 의사결정 지원은 KPI 비교표, 위험 분포, 민감도와 함께 제시하여 의사결정자가 불확실성을 인지하도록 한다.
  • 디지털 트윈 기반 '자율 운영'은 처방 결과를 자동 실행하되 인간 감독(Human-in-the-loop/on-the-loop)을 단계적으로 축소한다.

생성형 AI·LLM과 디지털 트윈

14.1LLM 기반 트윈 인터페이스와 RAG★★★물데모서▶
핵심 정리
  • LLM은 자연어 질의를 트윈 데이터 질의(SQL, Cypher, API 호출)로 변환하는 인터페이스로 사용된다(Text-to-SQL).
  • RAG(검색 증강 생성)는 설비 매뉴얼·작업 표준·고장 이력을 벡터 DB로 색인하고, 질의 시 관련 문서를 검색하여 근거 기반 답변을 생성한다.
  • 트윈 RAG는 정적 문서(매뉴얼)와 동적 상태(실시간 센서값)를 결합하여 '현재 상황에 맞는' 답변을 제공해야 한다.
  • 환각 방지를 위해 출처 인용, 수치 데이터는 도구 호출로 직접 조회, 답변 검증 단계를 둔다.
공식 · 구조
RAG 흐름
질의 q → 임베딩 e(q) → 유사도 top-k 검색(cos) → 프롬프트 [지시 + 문서 + 실시간 상태 + q] → 생성
코사인 유사도 = a·b / (‖a‖‖b‖)
강의 연계 · 실습 · 사례
실습RAG
설비 정비 Q&A 챗봇 구성 요소는?
매뉴얼 청크 분할 → 임베딩 → 벡터 DB 저장 → 질의 시 검색 + 실시간 경보 조회 도구 → LLM 응답 + 출처 표시이다.
오해 · 함정
주의LLM이 생성한 수치(온도·압력)를 그대로 신뢰하면 위험하다. 수치는 반드시 시계열 DB 조회 결과를 사용한다.
14.2AI 에이전트와 도구 호출★★★물데모서▶
핵심 정리
  • AI 에이전트는 LLM이 계획 → 도구 호출 → 결과 관찰 → 재계획의 루프(ReAct)를 수행하며, 트윈 API·시뮬레이터·최적화기를 도구로 사용한다.
  • MCP(Model Context Protocol)는 LLM 애플리케이션과 외부 데이터·도구를 연결하는 개방형 프로토콜로, 트윈 플랫폼을 MCP 서버로 노출하면 다양한 에이전트가 표준 방식으로 접근한다.
  • 다중 에이전트 구조(감시·진단·계획·실행 에이전트)는 역할 분리로 복잡한 운영 업무를 자동화한다.
  • 제어 명령은 위험도에 따라 사람 승인(approval gate), 권한 범위 제한, 감사 로그, 롤백 경로를 필수로 둔다.
공식 · 구조
ReAct 루프
Thought → Action(tool, args) → Observation → … → Final Answer
도구 결과가 다음 추론의 근거가 된다.
강의 연계 · 실습 · 사례
설계에이전트
이상 경보 대응 에이전트의 도구 목록을 설계하라
get_alarm, query_timeseries, search_manual, run_whatif_simulation, create_work_order(승인 필요)이다.
오해 · 함정
주의에이전트에 제어 쓰기 권한을 무제한으로 부여하는 것은 안전 원칙 위반이다. 최소 권한·승인 절차가 필요하다.
14.3합성 데이터와 생성 모델★★물데모서▶
핵심 정리
  • 합성 데이터는 트윈 시뮬레이션(렌더링·물리)이나 생성 모델(GAN, VAE, 확산 모델)로 생성하여 희소한 고장·결함 데이터를 보강한다.
  • 확산 모델은 노이즈를 점진적으로 제거하는 역과정을 학습하며, 시계열 확산 모델(TimeGrad, CSDI)은 결측 대체·시나리오 생성에 사용된다.
  • 합성 데이터 품질은 충실도(분포 유사성), 유용성(TSTR: 합성으로 학습·실데이터로 평가), 프라이버시(재식별 위험)로 평가한다.
  • 도메인 랜덤화는 사실성보다 다양성을 높여 실환경을 '분포 내 한 사례'로 만드는 전략이다.
공식 · 구조
확산 순방향
x_t = √(ᾱ_t)·x₀ + √(1 − ᾱ_t)·ε , ε ~ N(0, I)
신경망은 ε를 예측하도록 학습한다.
강의 연계 · 실습 · 사례

14.4월드 모델과 물리 AI★★물데모서▶
핵심 정리

  • 물리 기반 트윈(정확·해석 가능)과 학습형 월드 모델(범용·생성적)은 상호 보완 관계이며, 트윈이 월드 모델의 검증 기준을 제공한다.

14.5산업 기반 모델과 트윈 자동 생성★★물데모서▶

  • 텍스트→3D·이미지→3D 생성(확산 기반, 3DGS 기반)은 트윈 자산 제작 비용을 낮춘다.
  • 생성 결과는 공학적 검증(치수·물리·안전 규정)을 반드시 거쳐야 하며, 생성 이력과 검증 상태를 메타데이터로 관리한다.

제15편

트윈 인프라와 운영(TwinOps)

엣지-클라우드·컨테이너·MLOps·디지털 스레드·PLM
15.1엣지-클라우드 연속체 아키텍처★★물데모서▶
핵심 정리
  • 연산 배치는 지연 요구(제어 < 10 ms 엣지, 분석 초 단위 포그, 학습 분·시 단위 클라우드), 데이터량, 보안 요구로 결정한다.
  • 하이브리드 클라우드·온프레미스 구성은 데이터 주권과 규제(국가 핵심 기반시설) 요구를 충족한다.
  • 서버리스·이벤트 기반 처리는 간헐적 이벤트(경보)에, 상시 스트림 처리는 고빈도 텔레메트리에 적합하다.
  • 트윈 상태의 일관성은 최종 일관성(eventual)과 강한 일관성의 트레이드오프(CAP 정리)를 고려하여 설계한다.
공식 · 구조
종단 간 지연
T_e2e = T_sense + T_edge + T_net + T_queue + T_compute + T_render
각 구간 예산을 할당하여 병목을 관리한다.
강의 연계 · 실습 · 사례
설계연속체
제어·분석·학습 기능의 배치안을 제시하라
안전 인터록·PID는 PLC, 이상 탐지 추론은 엣지 GPU, 장기 예측·재학습·시뮬레이션은 클라우드에 배치한다.
오해 · 함정
주의CAP 정리상 네트워크 분할 시 일관성과 가용성을 동시에 보장할 수 없다. 현장 운전 연속성을 우선하는 설계가 일반적이다.
15.2컨테이너·쿠버네티스와 마이크로서비스★★물데모서▶
핵심 정리
  • 트윈 서비스(수집·변환·모델·시각화 API)를 마이크로서비스로 분리하고 컨테이너(Docker)로 패키징한다.
  • 쿠버네티스는 배포·확장·자가 치유를 자동화하며, 엣지에는 경량 배포판(K3s, MicroK8s)을 사용한다.
  • 인프라를 코드로 관리(IaC: Terraform, Helm)하고 GitOps(Argo CD, Flux)로 엣지 다수 사이트에 일관 배포한다.
  • 관측성(Observability)은 메트릭(Prometheus)·로그·분산 추적(OpenTelemetry)의 세 축으로 트윈 시스템 자체를 감시한다.
강의 연계 · 실습 · 사례
실습Docker Compose
실습용 트윈 스택 구성은?
mosquitto, influxdb, telegraf(수집), grafana, twin-api(FastAPI) 컨테이너를 compose 파일로 정의하고 네트워크·볼륨을 연결한다.
오해 · 함정
주의상태를 가진 시계열 DB를 일반 Deployment로 배포하면 재시작 시 데이터가 유실될 수 있다. StatefulSet·영구 볼륨을 사용한다.
15.3MLOps와 트윈 모델 수명주기★★★물데모서▶
핵심 정리
  • MLOps는 데이터 버전 관리 → 학습 파이프라인 → 모델 레지스트리 → 배포 → 모니터링 → 재학습의 자동화 체계이다.
  • 트윈 모델은 설비 열화·공정 변경으로 데이터 드리프트(입력 분포 변화)와 개념 드리프트(입출력 관계 변화)를 겪는다.
  • 드리프트 탐지는 PSI, KS 검정, 예측 잔차 추세로 수행하며, 임계 초과 시 재보정·재학습을 트리거한다.
  • 물리 모델·시뮬레이션 모델도 버전·파라미터·검증 결과를 함께 관리하는 'SimOps/TwinOps'가 필요하다.
공식 · 구조
PSI
PSI = Σ (Aᵢ − Eᵢ)·ln(Aᵢ / Eᵢ)
< 0.1 안정, 0.1~0.25 주의, > 0.25 유의한 변화로 본다.
강의 연계 · 실습 · 사례
실습MLflow
예측 모델 재학습 자동화 흐름은?
드리프트 감지 → 최근 데이터로 학습 파이프라인 실행 → 검증 지표 비교 → 레지스트리 승격 → 카나리 배포이다.
오해 · 함정
주의재학습 데이터에 이상 기간(고장·시험 운전)을 포함하면 정상 기준이 오염된다. 데이터 선별 규칙을 둔다.
15.4디지털 스레드와 PLM 연계★★물데모서▶
핵심 정리
  • 디지털 스레드는 요구사항 → 설계(CAD) → 해석(CAE) → 제조(CAM·MES) → 운용(트윈) → 폐기의 데이터를 추적 가능하게 연결하는 통신 프레임워크이다.
  • PLM(Teamcenter, Windchill, 3DEXPERIENCE)은 제품 구성(BOM)·변경 이력을 관리하며, eBOM → mBOM → sBOM으로 관점이 전환된다.
  • MBSE(모델 기반 시스템 공학, SysML v2)는 요구·기능·구조를 모델로 관리하여 트윈의 설계 근거를 제공한다.
  • 운용 트윈의 피드백(고장 데이터)이 차세대 설계로 환류되는 폐루프가 디지털 스레드의 핵심 가치이다.
공식 · 구조
BOM 관점
eBOM(설계) → mBOM(제조 공정) → sBOM(서비스·보전)
동일 제품의 목적별 구성 정보이다.

보안·신뢰성·거버넌스

IEC 62443·제로트러스트·데이터 주권·윤리·규제
16.1OT 보안과 IEC 62443★★★물데모서▶
핵심 정리
  • OT(운영기술) 보안은 가용성·안전을 최우선으로 하며(우선순위 A-I-C), IT 보안(C-I-A)과 우선순위가 다르다.
  • IEC 62443은 산업 자동화 제어 시스템 보안 표준 시리즈로, 영역(zone)과 도관(conduit) 기반 분할, 보안 수준(SL 0~4)을 정의한다.
  • 퍼듀 모델(Purdue Model) 계층 간 DMZ를 두고, 트윈 플랫폼은 OT→IT 단방향 데이터 흐름(데이터 다이오드)으로 수집하는 구성이 권장된다.
  • 트윈 자체가 공격 표면이 될 수 있으며(공장 구조·취약점 정보 집약), 트윈→설비 제어 경로는 가장 엄격한 통제가 필요하다.
  • 반대로 트윈은 사이버 공격 모의 훈련·이상 행위 탐지를 위한 '사이버 레인지'로 활용된다.
공식 · 구조
보안 수준 (IEC 62443-3-3)
SL1 우발적 위반 / SL2 단순 수단·낮은 자원의 의도적 공격 / SL3 정교한 수단·중간 자원 / SL4 정교한 수단·풍부한 자원(국가급)
영역별 목표 SL을 설정한다.
강의 연계 · 실습 · 사례
표준IEC 62443
영역과 도관 개념을 설명하라
영역은 동일 보안 요구를 가진 자산 묶음이고, 도관은 영역 간 통신 경로로서 보안 통제(방화벽·인증)가 적용되는 지점이다.
오해 · 함정
주의OT 시스템에 IT 방식의 자동 패치·능동 스캔을 그대로 적용하면 설비 정지를 유발할 수 있다.
16.2제로트러스트와 데이터 보호★★물데모서▶
핵심 정리
  • 제로트러스트는 '절대 신뢰하지 말고 항상 검증'하는 원칙으로 장치·사용자·서비스마다 인증·인가·암호화를 적용한다(NIST SP 800-207).
  • 장치 신원은 X.509 인증서·TPM·보안 요소로 관리하고, 통신은 TLS 1.3·mTLS로 보호한다.
  • 역할 기반(RBAC)·속성 기반(ABAC) 접근 제어로 트윈 데이터·명령 권한을 세분화한다.
  • 개인정보(작업자 위치·생체·영상)가 포함되는 경우 가명처리·최소 수집·목적 제한을 적용한다.
강의 연계 · 실습 · 사례
설계보안
트윈 원격 제어 기능의 보안 통제를 나열하라
다중 인증, 명령 단위 권한, 이중 승인, 명령 서명, 안전 인터록 확인, 감사 로그, 비상 정지 우선권이다.
오해 · 함정
주의VPN 접속만으로 내부망 전체를 신뢰하는 경계 기반 보안은 제로트러스트에 부합하지 않는다.
16.3데이터 주권과 데이터 공간★★물데모서▶
핵심 정리
  • 데이터 공간(Data Space)은 참여자가 데이터 통제권을 유지하면서 사용 정책(usage policy)과 함께 데이터를 공유하는 연합 인프라이다.
  • IDSA(International Data Spaces) 참조 아키텍처, Eclipse Dataspace Connector, Gaia-X 신뢰 프레임워크가 기반 기술이다.
  • Catena-X(자동차 공급망)는 AAS 기반 트윈과 데이터 공간을 결합하여 부품 추적·탄소 발자국(PCF) 교환을 구현한다.
  • EU 디지털 제품 여권(DPP, 에코디자인 규정)과 배터리 여권은 제품 수명주기 데이터를 트윈 형태로 제공하도록 요구한다.
강의 연계 · 실습 · 사례
사례Catena-X
공급망 트윈 데이터 공유가 필요한 이유는?
부품 단위 탄소 배출·리콜 추적을 위해 여러 기업 데이터가 필요하나, 기업 기밀 보호를 위해 주권 보장형 공유가 필요하다.
오해 · 함정
주의데이터를 중앙 플랫폼에 모두 업로드하는 방식은 데이터 공간이 아니다. 연합·정책 기반 공유가 핵심이다.
16.4신뢰할 수 있는 트윈 — 검증·설명성·윤리★★물데모서▶
핵심 정리
  • 트윈 신뢰성은 정확도, 충실도, 적시성, 견고성, 설명 가능성, 추적성의 측면에서 평가한다.

  • 인체·도시 트윈은 감시·프로파일링 우려가 있어 목적 제한과 이해관계자 참여 거버넌스가 필요하다.

제18편

디지털 트윈 프로젝트 실무

요구분석·로드맵·통합 실습·평가·사례 분석
18.1요구 분석과 유스케이스 정의★★★물데모서▶
핵심 정리
  • 트윈 프로젝트는 기술이 아니라 해결할 업무 문제(예: 비계획 정지 30% 감소)에서 출발하며, 측정 가능한 KPI로 목표를 정의한다.
  • 유스케이스별로 필요한 충실도(fidelity)·동기화 주기·예측 지평을 정의하는 '목적 적합(fit-for-purpose)' 원칙을 적용한다.
  • 이해관계자(운영·보전·IT·OT·경영)별 요구를 수집하고 데이터 가용성 진단(센서 유무, 품질, 접근성)을 병행한다.
  • 범위는 단일 고가치 설비 파일럿(PoC) → 라인 → 공장 → 전사 순으로 확장한다.
